# Artelier

An independent portfolio project by Oscar Avelar. Explore public-domain artworks from the Cleveland Museum of Art, search artists and titles, filter by medium and period, inspect artwork details, and build a browser-local collection.

## Stack

Next.js App Router conventions, React, TypeScript, TanStack Query and CSS. The Sites deployment uses Vinext's Next.js compatibility layer on Cloudflare Workers.

## Run

```sh
npm run dev
npm run build
```

## API and behavior

- `GET /api/artworks?q=monet&type=paintings&era=1800-1899&page=1` proxies and validates museum search requests.
- `GET /api/artworks/:id` retrieves artwork metadata and rejects images not marked public domain.
- Queries use cancellation, a five-minute client cache, previous-page placeholders and retry handling.
- Search is debounced by 400ms. Search, filters, page, collection view and artwork selection are reflected in the URL.
- Favorites use `localStorage` and stay on the current browser; no account or cross-device synchronization.
- The app handles upstream errors, network timeouts and rate limits. The default gallery presents museum highlights; search and category filters explore the broader open-access catalog.
- Search pagination is capped at 100 pages to avoid deep-pagination limits.

## Abuse protection

The public API routes use a shared D1 database, not per-instance in-memory counters:

- 30 API requests per client per fixed UTC minute. Only Cloudflare's trusted `CF-Connecting-IP` is used; missing metadata shares a conservative fallback bucket. Ordinary `X-Forwarded-For` headers cannot select a new bucket. The IP is hashed with a daily namespace and is never stored verbatim.
- Every cache miss must acquire a global slot with at least 500ms between admissions, shared across workers and routes, plus a 2,000-request daily UTC budget.
- Search responses cache for 6 hours; details cache for 24 hours. Stored responses can serve stale for an additional 24 hours during outages or quota exhaustion. Cache hits never call the museum.
- A museum `429` opens a shared circuit for at least 60 seconds and respects a longer `Retry-After`. Browser retries are disabled for 400, 404, 429 and 503.
- Protection database failures fail closed with 503. Quota errors return `Retry-After` and `Cache-Control: no-store`.
- Input length, allowed filters, numeric IDs, page bounds, duplicate parameters and unknown parameters are validated. Cache keys use normalized parameters. The upstream origin and path are fixed; redirects are rejected.
- Museum images are served directly by the museum CDN, separately from metadata API calls.

These controls bound traffic generated by this app; they do not guarantee the museum will never block requests, prevent someone contacting the museum directly, or replace an edge WAF against a large denial-of-service attack. The official CMA documentation does not specify a requests-per-second quota, so these are conservative application limits rather than a provider-guaranteed allowance.

Run `npm test` for local SQLite-backed quota, concurrency, cooldown, cache, spoofed-header and fail-closed checks. Tests mock outgoing HTTP requests; they do not load-test the museum. Apply the generated D1 migration before local preview; Sites applies it during deployment.
